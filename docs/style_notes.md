# SystemVerilog coding standard (kshell)

Ратифицированный свод. Всякий `.sv` обязан ему следовать И проходить lint-гейт
(`make lint`). Дополняй свободно — это общий контракт, не «предложение AI».

## 1. FSM — безопасный и двухпроцессный
- **Два процесса:** `always_comb` считает `state_d`/`phase_d` **и ТОЛЬКО выходные
  сигналы** (порты: `m_t*`, `s_tready` …). `always_ff` только регистрирует
  `state_q <= state_d`. Логику next-state в `ff` не пишем.
- **В `always_comb` НЕ вычисляем промежуточные/вспомогательные значения, которые потом
  регистрируются.** Каждый такой регистр (`widx_q`, `hdr_ok_q`, `res_q`, `m_tkeep_d` …)
  живёт в **своём маленьком `always_ff`** — считает свой next-value сам. Комбинаторный
  блок = «выходы + next-фаза», не «пересчёт всего состояния».
- **`case (state_q) … default:` — обычный, БЕЗ `unique`/`priority`.** `unique` разрешает
  синтезу выкинуть `default` как недостижимый → нет безопасного восстановления из
  нелегального состояния. `default:` ВСЕГДА ведёт в безопасное состояние (обычно IDLE).
- **Состояния — именованный `enum logic [..]`**, не магические счётчики/сравнения индексов.
- **Против латчей:** в начале `always_comb` присваиваем ВСЕ выходы/`*_d` дефолтами,
  дальше только переопределяем. Полное покрытие всех веток.

## 2. Регистры и присваивания
- **`always_ff` — только неблокирующие `<=`. `always_comb` — только блокирующие `=`.**
  Никогда не смешивать в одном блоке.
- **Один `always_ff` на когезивную группу (1–3 связанных регистра)**, разбитый по
  концернам (валидация / датапат / хвост — каждый свой блок). НЕ один мега-блок.
- **Датапат-регистры — resetless**, если они гарантированно загружаются до чтения
  (напр. `res_q`, `m_tkeep_d`): `always_ff @(posedge clk) if (cond) r <= …;` без ветки
  `!rst_n`. Меньше reset-fanout, лучше пакуется. Reset держим на УПРАВЛЕНИИ (фаза,
  счётчики, флаги), не на чистом датапате.
- Думать **синтезом, а не симуляцией**: у регистра есть next-value = комбинаторная
  функция состояния и входов (описываем мультиплексоры), а не «сделать X, потом Y».

## 2a. Low-latency идиомы (короткий hot path)
- **`tkeep` — префиксная маска → битовая нарезка вместо арифметики.** «Валидных байт
  > K?» = `tkeep[7:K] != 0` (reduction-OR, 1 LUT), НЕ `$countones(tkeep) > K` (popcount =
  дерево сумматоров). Слить keep = конкатенация срезов (`{tkeep[1:0], 6'b111111}`), НЕ
  переменный сдвиг `0xFF >> (…)`. Сдвиг keep на константу = `tkeep >> N` (разводка).
- Тяжёлую комбинаторику с hot-path **выносим в регистр заранее** (напр. `m_tkeep_d`
  считается на такте приёма, а в FLUSH берётся готовым — 0 логики на выходе).
- Общий принцип: на критическом пути — мукс/срез/OR, не popcount/переменный shift/сумматор.

## 3. Reset
- **Синхронный** (проектная конвенция): `always_ff @(posedge clk); if (!rst_n) …`.
  Обоснование: FF инициализируются из битстрима (Xilinx GSR); sync даёт лучший тайминг,
  без recovery/removal, и позволяет упаковку в DSP/BRAM/SRL (async ломает — урок gemm).
- Никакого `negedge rst_n` в списке чувствительности датапат-регистров.

## 4. Ассершены
- **Отдельный файл `rtl/<module>_sva.sv`, `bind <module> … (.*)`** — рядом с RTL, не в tb/,
  не inline. Дизайн и проверки разделены, но колокированы. Синтез `*_sva.sv` не читает:
  список дизайн-файлов — как `RTL_DESIGN` в `scripts/Makefile` (без `*_sva.sv`/`*_cov.sv`);
  синтез-скрипта в этом репозитории нет (только симуляция).

## 5. Именование / ширины / числа
- lowRISC: `lower_snake_case`, один модуль на файл, суффиксы `_q`/`_d` для рег/next.
- **Явные ширины** во всех литералах/срезах; никаких неявных расширений.
- **Магические числа → `localparam`** с говорящим именем (размеры заголовков, офсеты).
- Комментарии объясняют **«зачем»/hw-интент**, не пересказывают код.

## 6. Робастность
- Не предполагать «идеальный» вход молча. Границы (обрыв пакета, переполнение,
  нелегальные длины) — обрабатывать или ЯВНО документировать как вне scope.

## 7. Lint-гейт (обязательно перед показом кода)
```bash
make lint            # verible-verilog-lint + verilator --lint-only на все rtl/*.sv
make fmt             # verible-verilog-format (авто-форматирование)
```
Модуль не показывается, пока `make lint` не чист. Правила Verible — в `.rules.verible`.

## 8. Coverage (code + functional)
Нетривиальный модуль сопровождается **покрытием** — это часть верификации, а не
опция. Тулчейн-ловушки — ниже в этом разделе.
- **Code coverage** — Verilator `--coverage` (line/toggle/branch/expr). Прогон:
  `make cov TOP=<mod> MODULE=test_<mod>` → аннотация в `annot/`, строки `%00` — дыры.
- **Functional coverage** — SV `covergroup` в **отдельном bind-файле `rtl/<mod>_cov.sv`**
  (рядом с `_sva.sv`; синтез не читает; собирается только под `VCOV=1`). Покрываем:
  состояния/дуги FSM, спец-значения протокола, seq-отношения, размеры хвостов, backpressure,
  предельное заполнение буферов.
- **⚠️ Ассершены и coverage — РАЗДЕЛЬНЫЕ прогоны:** Verilator 5.x падает Internal Error на
  `--coverage + --assert` вместе (Makefile разводит: обычный прогон = `--assert`+`_sva`,
  `VCOV=1` = `--coverage`+`_cov`).
- **⚠️ Covergroup Verilator = урезанное подмножество:** только ЯВНЫЙ `cg.sample()` (встроенный
  `@(posedge)` молча не эмитит), именованные `bins`, условие внешним `if()` вместо `iff`;
  `transition (a=>b)` НЕ поддержано (arc — вручную через `{prev,cur}`). Семплить с
  **синхронного снимка** (`_r`-регистры), иначе дельта-гонка bound-covergroup даёт мусор.
- **Closure-петля:** пустой бин = дыра в тестах → направленный стимул (`test_*_closure`),
  либо `ignore_bins`/комментарий, если бин недостижим по конструкции. Не оставляем «молча 0».
