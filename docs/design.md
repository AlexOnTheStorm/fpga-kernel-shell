# kshell — универсальная обёртка вычислительного ядра: спецификация

> **Назначение.** Компактная демонстрация «обвязки между ядром и топ-левелом» для FPGA-ускорителя инференса: ядро получает узкий контракт (поток, scratchpad, start/done), а обёртка берёт на себя AXI, транзакции в полёте, out-of-order ответы памяти, синхронизацию через семафоры, ошибки, безопасную остановку и perf-счётчики.
> **Статус:** спецификация. Проверка — симуляция (cocotb + Verilator), не кремний.
> **Стиль RTL:** `docs/style_notes.md` (синхронный сброс `rst_n`, датапат без сброса, двухпроцессные FSM, SVA и coverage — отдельными bind-файлами).

---

## 1. Объём

**В объёме:**
- обёртка `kshell`: AXI4-Lite slave для хоста, AXI4 master 256 бит к памяти, командная очередь, секвенсор, rd-DMA (LOAD, STREAM), wr-DMA (STORE), scratchpad, семафоры, ошибки, quiesce, watchdog, perf-счётчики;
- демо-ядро `gemv_kernel` (INT8 GEMV);
- верхний уровень `kshell_top` = `kshell` + `gemv_kernel`;
- верификация: модели памяти и хоста на Python, системные и модульные тесты, SVA, функциональное покрытие.

**Вне объёма** (сознательно): синтез и timing closure, CDC (один тактовый домен), несколько ядер, интерконнект, кредитные линки, прерывания (хост опрашивает регистры), доступ ядра к памяти по вычисляемым адресам, перекрытие внутри ядра (ядро не видит семафоров).

## 3. Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `DW` | 256 | ширина данных AXI4 MM, AXIS и scratchpad |
| `AW` | 40 | ширина адреса AXI4 MM |
| `NTAG` | 16 | слотов в окне rd_dma = максимум burst'ов чтения в полёте (степень 2) |
| `BURST` | 8 | beat'ов в burst'е (256 B при DW = 256) |
| `WR_OUT` | 8 | максимум burst'ов записи в полёте |
| `SPM_WORDS` | 1024 | слов scratchpad по DW бит (32 KB) |
| `NSEM` | 8 | число семафоров |
| `CQ_DEPTH` | 16 | глубина командной FIFO |
| `EQ_DEPTH` | 4 | глубина очереди каждого движка |
| `WDOG_CYCLES` | 2^20 | порог watchdog (в тестах меньше) |

Производные: `BB = DW/8` (байт на beat) = 32, `BURST_BYTES = BURST × BB` = 256.

## 4. Внешние интерфейсы `kshell_top`

- `clk`, `rst_n` — один домен, синхронный сброс, активный низкий.
- `s_axil_*` — AXI4-Lite slave, 32 бита данных, 12 бит адреса. Ответ всегда OKAY; чтение незанятого адреса возвращает 0.
- `m_axi_*` — AXI4 master, `DW` = 256, все пять каналов:
  - `ARID` = номер слота (log2 NTAG бит), `ARLEN` = BURST−1, `ARSIZE` = log2(BB), `ARBURST` = INCR, `ARCACHE` = `0011`;
  - `AWID` = 0 (константа), `AWLEN`/`AWSIZE`/`AWBURST` — как у AR, `AWCACHE` = `0010` (non-bufferable: B означает «данные в памяти»);
  - `WSTRB` = все единицы (STORE пишет полные слова);
  - `RREADY` = 1 всегда (§8.4), `BREADY` = 1 всегда;
  - `AxPROT` = `000`, `AxQOS` = 0, `AxLOCK` = 0.

## 5. Контракт с ядром

| Группа | Сигнал | Направление | Описание |
|---|---|---|---|
| Управление | `k_start` | shell → ядро | импульс 1 такт; запуск |
| | `k_arg[4][31:0]` | shell → ядро | аргументы, действительны в такте `k_start` (ядро защёлкивает) |
| | `k_done` | ядро → shell | импульс 1 такт; ровно один на каждый `k_start` |
| | `k_err` | ядро → shell | импульс; нарушение контракта, замеченное ядром |
| Поток | `k_s_tdata[DW]`, `k_s_tvalid`, `k_s_tready`, `k_s_tlast` | shell → ядро | AXI4-Stream; данные команд STREAM строго по порядку; `tlast` — на последнем beat'е каждой команды STREAM |
| Scratchpad | `k_spm_en`, `k_spm_we`, `k_spm_addr[log2 SPM_WORDS]`, `k_spm_wdata[DW]`, `k_spm_wstrb[DW/8]`, `k_spm_rdata[DW]` | ядро ↔ shell | порт B; чтение — данные через 1 такт после `en && !we` |

**Правила для автора ядра:**
1. Ядро обязано принять все beat'ы, которые программа направила ему командами STREAM. Если не принимает, поток стоит, а за ним стоит коммит rd_dma (§8.5).
2. Порт B scratchpad принадлежит только ядру. Обёртка через порт B не обращается.
3. Не читать и не писать область scratchpad, в которую идёт LOAD или из которой идёт STORE. Это обязанность программы: она ставит WAIT на семафор этих команд.
4. Один `k_done` на каждый `k_start`. Новый `k_start` не приходит, пока не выдан `k_done` предыдущего.
5. Смысл аргументов определяет ядро, обёртка передаёт их как есть.

## 6. Модель программирования и формат команд

Хост записывает `CMD0..CMD3`, затем пишет любое значение в `DOORBELL`. Если командная FIFO полна, запись в `DOORBELL` игнорируется, и выставляется липкий флаг `STATUS.cq_ovf`. Хост обязан проверять `cq_free` перед записью.

**Дескриптор (128 бит):**

| Поле | Биты | Описание |
|---|---|---|
| `op` | `CMD0[31:28]` | код команды |
| `sem` | `CMD0[26:24]` | номер семафора (log2 NSEM бит) |
| `spm_addr` | `CMD0[15:0]` | адрес в scratchpad, в словах |
| `hbm_lo` | `CMD1[31:0]` | адрес в памяти, младшие 32 бита |
| `hbm_hi` | `CMD2[7:0]` | адрес в памяти, старшие 8 бит |
| `len` | `CMD3[31:0]` | длина в байтах |

| `op` | Команда | Используемые поля | Семантика | Завершена, когда |
|---|---|---|---|---|
| 1 | `LOAD` | `sem`, `spm_addr`, `hbm`, `len` | память → spm | все burst'ы пришли и закоммичены по порядку; тогда `sem += 1` |
| 2 | `STREAM` | `hbm`, `len` | память → AXIS ядра | последний beat принят ядром |
| 3 | `STORE` | `sem`, `spm_addr`, `hbm`, `len` | spm → память | получены все B; тогда `sem += 1` |
| 4 | `WAIT` | `sem`; `CMD1` = порог `thr` | секвенсор стоит, пока `$signed(sem − thr) >= 0` не станет истинным | условие истинно |
| 5 | `SIGNAL` | `sem`; `CMD1` = `inc` | `sem += inc` | сразу |
| 6 | `RUN` | `sem`; `arg0` = `CMD1`, `arg1` = `CMD2`, `arg2` = `CMD3`, `arg3` = `CMD0[15:0]` (с расширением нулями) | запуск ядра | `k_done`; тогда `sem += 1` |
| 0, 7–15 | — | — | ошибка `BAD_OPCODE` | — |

**Проверки при декодировании** (ошибка → команда не выполняется, §12):
- `LOAD`/`STREAM`/`STORE`: `len ≠ 0`, `len % BURST_BYTES = 0`, `hbm % BURST_BYTES = 0`, иначе `ALIGN`;
- `LOAD`/`STORE`: `spm_addr + len/BB ≤ SPM_WORDS`, иначе `RANGE`.

Граница 4 KB не пересекается автоматически: burst'ы выровнены по 256 B, а 4096 кратно 256.

**Пример: две задачи GEMV с двойной буферизацией `x`** (`W` один, `x0` и `x1` разные):

```
LOAD   sem0, spm=XA, hbm=x0, len=K
LOAD   sem0, spm=XB, hbm=x1, len=K
STREAM hbm=W, len=M·K                ; веса начинают идти до старта ядра (заполняют окно и ROB)
WAIT   sem0 ≥ 1
RUN    sem1, x=XA, y=YA, M, K        ; пока считает — x1 уже грузится
STREAM hbm=W, len=M·K
WAIT   sem0 ≥ 2
RUN    sem1, x=XB, y=YB, M, K
WAIT   sem1 ≥ 2
STORE  sem2, spm=YA, hbm=y0, len=4·M
STORE  sem2, spm=YB, hbm=y1, len=4·M
WAIT   sem2 ≥ 2
SIGNAL sem7, 1                       ; хост опрашивает SEM[7]
```

(Для простоты `4·M` кратно 256, то есть M кратно 64; K кратно 256.)

**Правило для программ:** STREAM для RUN выдаётся **до** этого RUN. Тогда при ошибке (секвенсор останавливается) все потоки, которых ждут уже запущенные ядра, гарантированно доставлены, и ядро не зависнет. Программа, нарушившая правило, может после ошибки зависнуть — это поймает watchdog (`TIMEOUT`).

## 7. Секвенсор `cmd_seq`

- Берёт дескриптор из командной FIFO, когда `CTRL.ENABLE = 1`, нет ошибки и нет запроса halt. Не больше одной команды за такт.
- Номер команды `cmd_seq_no` (32 бита) увеличивается на каждую взятую команду; попадает в `ERR_CMD` при ошибке.
- Проверяет команду (§6). LOAD и STREAM идут в очередь rd, STORE — в очередь wr, RUN — в очередь ядра. Если нужная очередь полна, секвенсор стоит, это perf `SEQ_QFULL`.
- `WAIT` блокирует выдачу следующих команд, это perf `SEQ_WAIT`. `SIGNAL` выполняется сам.
- Движки работают независимо и параллельно. Порядок между ними задаёт только WAIT.
- Запуск ядра: команды из очереди ядра обёртка выдаёт как `k_start`, когда ядро свободно (`krn_busy = 0`). `krn_busy` ставится по `k_start` и снимается по `k_done`. По `k_done` — `sem += 1` для семафора этого RUN.

## 8. rd-DMA (LOAD и STREAM)

### 8.1. Нарезка и выдача AR
Команда из очереди rd режется на `len / BURST_BYTES` burst'ов. Burst выдаётся, если в окне есть свободный слот. Слот = `tail[log2 NTAG − 1:0]`, `ARID` = номер слота, адрес = `hbm + i × BURST_BYTES`. Не больше одного AR за такт. Окно заполнено → AR не выдаются (perf `RD_WIN_FULL`); ожидание `ARREADY` — perf `RD_AR_STALL`.

### 8.2. Слот окна
`{type (LOAD/STREAM), spm_addr (для LOAD — адрес первого слова burst'а), beat_cnt, done, last_of_cmd, sem, err, t_issue}`. `t_issue` — значение счётчика тактов в момент AR, нужно для perf `RD_LAT_SUM`.

### 8.3. Приём R
Beat с `RID = s`:
- `type = LOAD` → запись в spm через порт A по адресу `spm_addr[s] + beat_cnt[s]`, сразу, без переупорядочивания;
- `type = STREAM` → запись в ROB по адресу `{s, beat_cnt[s]}`. ROB — память `NTAG × BURST` слов по DW;
- `beat_cnt[s] += 1`; на `RLAST` → `done[s] = 1`, к `RD_LAT_SUM` добавляется `now − t_issue[s]`;
- `RRESP ≠ OKAY` → `err[s] = 1` и ошибка `RRESP_ERR` (§12). Данные всё равно записываются и выдаются (§12).

Beat'ы разных ID могут чередоваться: счётчики beat'ов независимы по слотам.

### 8.4. `RREADY = 1` всегда
Запись из R не может застрять: место в spm (LOAD) или в ROB (STREAM) зарезервировано за слотом заранее, а порт A spm у R-записей имеет абсолютный приоритет (§10). Канал R поэтому никогда не тормозит память.

### 8.5. Коммит по порядку (голова окна)
- голова `LOAD` и `done` → снять слот; если `last_of_cmd`, то `sem += 1`, если в команде не было ошибки. Не больше одного слота за такт;
- голова `STREAM` и `done` → выдать BURST beat'ов из ROB в AXIS ядра (чтение ROB с задержкой 1 такт, на выходе skid-регистр). `tlast` ставится на последнем beat'е burst'а с `last_of_cmd`. После последнего beat'а слот снимается.

**Head-of-line blocking (сознательно).** Если ядро не принимает поток, голова STREAM стоит, и коммит последующих LOAD ждёт. Это видно в perf `STRM_BP`. Альтернатива — раздельные окна LOAD и STREAM: дороже, нужен второй пул тегов. Описана как вариант, не реализуется.

## 9. wr-DMA (STORE)

- Команда режется на burst'ы. На каждый burst: выдать AW, затем прочитать BURST слов spm через порт A (только в такты, когда порт свободен от R-записей) в W-FIFO глубиной 2 × BURST, из неё — W с `WLAST` на 8-м beat'е.
- AW выдаётся, только если burst'ов записи в полёте меньше `WR_OUT` и в W-FIFO есть место под burst. W для burst'а i не начинается раньше его AW.
- `AWID` = 0 для всех burst'ов → B приходят по порядку. Счётчик «выдано AW минус получено B». Когда получены все B команды → `sem += 1`, если ошибок не было.
- `BRESP ≠ OKAY` → ошибка `BRESP_ERR`.
- Perf: `WR_BURSTS`, `WR_STALL` (такты ожидания `AWREADY` или `WREADY`).

---

## 10. Scratchpad `spm`

- `SPM_WORDS × DW`, два порта. Порт A — DMA, порт B — ядро. Чтение с задержкой 1 такт, побайтовая маска записи на обоих портах.
- Арбитр порта A: R-записи rd_dma имеют абсолютный приоритет; wr_dma читает в свободные такты.
- Одновременное обращение портов A и B к одному адресу — запрещено контрактом (§5, правило 3); проверяется SVA, поведение памяти в этом случае не определено.

---

## 11. Семафоры `sem_file`

- `NSEM` 32-битных счётчиков.
- Источники приращений в одном такте: коммит rd_dma (+1), завершение wr_dma (+1), `k_done` (+1), `SIGNAL` (+inc). Приращения на один и тот же семафор суммируются.
- Запись хоста в `SEM[i]` задаёт значение и имеет приоритет над приращениями в том же такте.
- Сравнение для WAIT — знаковая разность (безопасно при переполнении, пока значения не разошлись больше чем на 2^31).

## 12. Ошибки, quiesce, watchdog, сброс

**Коды `ERR_CODE`:** 0 — нет, 1 — `RRESP_ERR`, 2 — `BRESP_ERR`, 3 — `ALIGN`, 4 — `RANGE`, 5 — `BAD_OPCODE`, 6 — `KERNEL_ERR`, 7 — `TIMEOUT`. Фиксируется **первая** ошибка; `ERR_CMD` — номер её команды (для `KERNEL_ERR` и `TIMEOUT` — номер последней выданной команды).

**Политика при ошибке:**
1. `STATUS.ERROR = 1`, секвенсор больше не берёт команды.
2. Движки **дорабатывают всё, что уже выдано**: все AR получают свои R, все AW — свои W и B. Ни одна транзакция AXI не бросается.
3. Ошибочная LOAD не увеличивает семафор. STREAM с ошибкой отдаёт ядру все beat'ы, чтобы ядро не зависло; результат недействителен.
4. `CTRL.CLR_ERR` сбрасывает ошибку только в состоянии IDLE.

**IDLE:** командная FIFO и очереди движков пусты, окно rd пусто, записей в полёте 0, W-FIFO пуста, ядро свободно, выход AXIS пуст.

**Quiesce (`CTRL.HALT_REQ = 1`):** секвенсор не берёт новые команды; уже выданные дорабатываются; когда наступает IDLE → `STATUS.HALTED = 1`. Незавершённый WAIT считается границей команды: halt наступает и во время ожидания, а после снятия `HALT_REQ` условие WAIT проверяется заново. Снятие `HALT_REQ` возобновляет работу с того же места очереди. (Для IDLE в этом случае командная FIFO может быть не пуста — `HALTED` требует пустоты всего, кроме командной FIFO и текущего WAIT.)

**Watchdog:** счётчик тактов без прогресса (R-beat, B, beat AXIS, `k_done`, выдача команды). Если не IDLE и счётчик достиг `WDOG_CYCLES` → `TIMEOUT`. Изнутри такое не лечится: нужен внешний сброс домена (в реальной системе — через decoupler, который завершает зависшие транзакции).

**`CTRL.SOFT_RESET`:** выполняется только в IDLE (иначе игнорируется). Сбрасывает очереди, указатели, ошибку, счётчик команд; семафоры обнуляются. Так как после дренажа в полёте ничего нет, «опоздавших» ответов не бывает и бит эпохи в ID не нужен.

## 13. Регистры (AXI4-Lite)

| Адрес | Имя | Доступ | Поля |
|---|---|---|---|
| `0x000` | `CTRL` | RW | `[0] ENABLE`, `[1] HALT_REQ`; самосбрасывающиеся: `[2] SOFT_RESET`, `[3] CLR_ERR`, `[4] PERF_SNAP`, `[5] PERF_CLR` |
| `0x004` | `STATUS` | RO | `[0] IDLE`, `[1] HALTED`, `[2] ERROR`, `[3] cq_ovf` (липкий, сбрасывается `CLR_ERR`), `[15:8] cq_free`, `[23:16] rd_inflight`, `[31:24] wr_inflight` |
| `0x008` | `ERR_CODE` | RO | `[3:0]` |
| `0x00C` | `ERR_CMD` | RO | номер команды |
| `0x010`–`0x01C` | `CMD0`–`CMD3` | WO | дескриптор |
| `0x020` | `DOORBELL` | WO | запись = положить дескриптор в FIFO |
| `0x024` | `CMD_COUNT` | RO | `cmd_seq_no` |
| `0x040 + 4i` | `SEM[i]` | RW | значение семафора i |
| `0x080…` | `PERF_*` | RO | снимки (§14) |

## 14. Perf-счётчики `kshell_perf`

32-битные счётчики, работают при `ENABLE`; `PERF_SNAP` копирует все в регистры чтения одновременно, `PERF_CLR` обнуляет.

| Адрес | Имя | Что считает |
|---|---|---|
| `0x080` | `CYCLES` | такты |
| `0x084` | `SEQ_WAIT` | такты секвенсора на WAIT |
| `0x088` | `SEQ_QFULL` | такты секвенсора из-за полной очереди движка |
| `0x08C` | `RD_BURSTS` | выданные burst'ы чтения |
| `0x090` | `RD_LAT_SUM` | сумма задержек AR → RLAST; средняя задержка = `RD_LAT_SUM / RD_BURSTS` |
| `0x094` | `RD_WIN_FULL` | такты, когда AR есть что выдать, но окно полно |
| `0x098` | `RD_AR_STALL` | такты `ARVALID && !ARREADY` |
| `0x09C` | `STRM_BP` | такты `k_s_tvalid && !k_s_tready` |
| `0x0A0` | `WR_BURSTS` | выданные burst'ы записи |
| `0x0A4` | `WR_STALL` | такты `(AWVALID && !AWREADY) \|\| (WVALID && !WREADY)` |
| `0x0A8` | `KRN_BUSY` | такты `krn_busy` |

## 15. Демо-ядро `gemv_kernel`

**Функция:** `y[m] = Σ_k W[m][k] · x[k]`, `W` и `x` — INT8 со знаком, накопление и `y` — INT32 со знаком (переполнение — по модулю 2^32, как в эталоне).

**Аргументы:** `arg0` — адрес `x` в spm (слова), `arg1` — адрес `y` в spm (слова), `arg2` — `M`, `arg3` — `K` (кратно 32).

**Раскладка:**
- `x`: K/32 слов, элемент k — в байте `k % 32` слова `k / 32`;
- `W`: поток строк, строка m — K/32 beat'ов, элемент k — в байте `k % 32` beat'а `k / 32`; всего M·K/32 beat'ов;
- `y`: 8 значений на слово, `y[m]` — в дорожке `m % 8` слова `arg1 + m / 8`, запись по `wstrb` на 32-битную дорожку.

**Микроархитектура:**
- на каждый принятый beat `W` — слово `x[beat % (K/32)]`, прочитанное из spm с опережением на такт;
- 32 умножения INT8 → дерево сумматоров (конвейер) → аккумулятор строки;
- в конце строки — запись `y[m]` через порт B. Чтение `x` и запись `y` делят порт B, поэтому на границе строки возможен пропуск такта (`tready = 0`).
- Целевой темп в установившемся режиме — 1 beat за такт, за вычетом пауз на границах строк.

**`k_err`:** `tlast` пришёл не на beat'е M·K/32, или на этом beat'е его нет.

**`k_done`:** после записи последнего `y`.

## 16. Верификация

**Инфраструктура** — как в tick_to_trade: cocotb + Verilator, `make lint` (Verilator `-Wall` + Verible), прогоны с ассершенами и с покрытием раздельно (`VCOV=1`), SVA и covergroup в bind-файлах `rtl/<mod>_sva.sv` и `rtl/<mod>_cov.sv`.

**Модели на Python (`tb/`):**
- `hbm_model` — AXI4 slave:
  - память словарём байтов;
  - `N_PC` псевдоканалов (по умолчанию 8), PC = `(addr >> 8) % N_PC`;
  - у каждого PC очередь и случайная задержка из настраиваемого диапазона → ответы **out-of-order по ID**;
  - опционально чередование R-beat'ов разных ID;
  - случайные паузы `ARREADY`/`AWREADY`/`WREADY`;
  - B — по порядку для одного ID;
  - впрыск `SLVERR` по заданным адресам;
  - проверка протокола на стороне модели: `WLAST`, `AxLEN`, граница 4 KB.
- `axil` — драйвер AXI4-Lite.
- `isa` — кодировщик дескрипторов и помощник для программ (`load()`, `stream()`, `store()`, `wait()`, `signal()`, `run()`).
- Эталон GEMV на numpy.

**Тесты:**

| # | Тест | Проверяет |
|---|---|---|
| T1 | memcpy: LOAD → STORE через spm, разные длины | данные, семафоры, OoO-ответы |
| T2 | STREAM в ядро-приёмник (тестовое ядро, пишущее поток в spm) | порядок потока при OoO, `tlast` |
| T3 | GEMV, несколько (M, K) | результат против numpy |
| T4 | две задачи с двойной буферизацией (программа §6) | результат; общее время меньше, чем у той же работы без перекрытия (последовательная программа) |
| T5 | впрыск SLVERR в LOAD, STREAM и STORE | `ERROR`, код, `ERR_CMD`; дренаж; нет зависания; `CLR_ERR` в IDLE |
| T6 | `HALT_REQ` посреди программы, затем продолжение | `HALTED` только в IDLE; результат после продолжения верный |
| T7 | ошибки декодирования: `ALIGN`, `RANGE`, `BAD_OPCODE`, переполнение командной FIFO | коды, `cq_ovf` |
| T8 | watchdog: модель памяти перестаёт отвечать | `TIMEOUT` |
| T9 | случайные программы LOAD/STORE/SIGNAL/WAIT | память и семафоры против Python-модели |

Модульные тесты — для `rd_dma` (с моделью памяти и приёмником потока) и `sem_file`; остальное покрывается системными.

**SVA (основное):**
- AXI4 master: `VALID` держится до handshake, полезная нагрузка стабильна; `ARLEN`/`AWLEN` = BURST−1; burst не пересекает 4 KB; число W-beat'ов на AW = BURST, `WLAST` на последнем;
- окно rd: R только для слота в полёте; `beat_cnt ≤ BURST`; `tail − head ≤ NTAG`;
- AXIS к ядру: стабильность при `tvalid && !tready`;
- spm: нет одновременной записи в порт A от двух источников; нет одновременного доступа A и B к одному адресу;
- `k_done` только при `krn_busy`.

**Функциональное покрытие:**
- окно заполнено;
- расстояние out-of-order (насколько далеко от головы пришёл ответ): бины 0, 1–3, 4–7, 8+;
- чередование beat'ов разных ID;
- head-of-line блокировка (голова STREAM стоит при готовых LOAD за ней);
- все коды команд; стоянка на WAIT;
- все коды ошибок;
- HALT во время трафика;
- W-FIFO полна; одновременные приращения одного семафора.

**Демо (`scripts/demo`):** прогон T4 с печатью отчёта perf-счётчиков: средняя задержка чтения, занятость ядра, `STRM_BP`, `SEQ_WAIT`, время с перекрытием и без. Числа в README помечаются «симуляция с моделью памяти, не кремний».

## 17. Проектные решения (для разговора)

| Решение | Почему | Альтернатива и её цена |
|---|---|---|
| Ядро без AXI, контракт поток + spm + start/done | вся сложность памяти — один раз в обёртке; ядро можно отдать контрактору как black box; DMA можно поставить у HBM, ядро — где угодно | AXI в каждом ядре: повторение тегов, OoO, ошибок; утечка системы к контрактору |
| Тег = номер слота окна | коммит по порядку бесплатен (как ROB); тег не нужно хранить | свободный список тегов: нужен отдельный ROB по порядку выдачи |
| LOAD пишет OoO, семафор — по порядку | данные не надо переупорядочивать; потребитель видит только подряд готовое | переупорядочивать данные: лишняя память |
| `RREADY = 1` | память никогда не стоит из-за обёртки; место зарезервировано заранее | backpressure на R: потеря полосы памяти |
| Один `AWID`, `AWCACHE = 0010` | записи не нужно переставлять; B означает «в памяти» — семафор не врёт | bufferable-записи: быстрее, но B раньше данных |
| Одно окно на LOAD и STREAM | проще, один пул тегов | раздельные окна: нет head-of-line блокировки, вдвое больше состояния |
| Синхронизация только через семафоры + WAIT | модель командных потоков NPU/TPU: программа явно задаёт зависимости, движки параллельны | неявные зависимости в железе: сложнее и менее гибко |
| Сброс только после дренажа | ни одна транзакция AXI не бросается; бит эпохи не нужен | сброс в любой момент: нужен decoupler и эпохи |
