# kshell — универсальная обёртка вычислительного ядра: спецификация

> **Назначение.** Компактная демонстрация «обвязки между ядром и топ-левелом» для FPGA-ускорителя инференса: ядро получает узкий контракт (поток, scratchpad, start/done, сброс), а обёртка берёт на себя AXI, транзакции в полёте, out-of-order ответы памяти, синхронизацию через семафоры, ошибки, безопасную остановку и perf-счётчики.
> **Статус:** спецификация, ревизия 3 (синхронизирована с реализацией). Проверка — симуляция (cocotb + Verilator), не кремний.
> **Стиль RTL:** `docs/style_notes.md` (синхронный сброс `rst_n`, датапат без сброса, двухпроцессные FSM, SVA и coverage — отдельными bind-файлами).

---

## 1. Объём

**В объёме:**
- обёртка `kshell`: AXI4-Lite slave для хоста, AXI4 master 256 бит к памяти, командная очередь, секвенсор, rd-DMA (LOAD, STREAM), wr-DMA (STORE), scratchpad, семафоры, ошибки, пауза и сброс с транзакциями в полёте, watchdog, perf-счётчики;
- демо-ядро `gemv_kernel` (INT8 GEMV);
- `kshell_kif_sva` — исполняемый контракт для авторов ядер: bind-файл с ассершенами интерфейса ядра;
- верхний уровень `kshell_top` = `kshell` + `gemv_kernel`;
- верификация: модели памяти и хоста на Python, статический проверщик программ, системные и модульные тесты, SVA, функциональное покрытие, демо со свипом «NTAG × задержка памяти».

**Вне объёма** (сознательно): синтез и timing closure, CDC (один тактовый домен), несколько ядер, интерконнект, кредитные линки, прерывания (хост опрашивает регистры), доступ ядра к памяти по вычисляемым адресам, перекрытие внутри ядра (ядро не видит семафоров), сброс при незавершённых транзакциях AXI (§12.4).

## 3. Параметры

| Параметр | По умолчанию | Смысл |
|---|---|---|
| `DW` | 256 | ширина данных AXI4 MM, AXIS и scratchpad |
| `AW` | 40 | ширина адреса AXI4 MM |
| `NTAG` | 16 | слотов в окне rd_dma = максимум burst'ов чтения в полёте (степень 2) |
| `BURST` | 8 | beat'ов в burst'е (256 B при DW = 256) |
| `WR_OUT` | 8 | максимум burst'ов записи в полёте |
| `SPM_WORDS` | 1024 | слов scratchpad по DW бит (32 KB) |
| `NSEM` | 8 | число семафоров |
| `CQ_DEPTH` | 16 | глубина командной FIFO |
| `EQ_DEPTH` | 4 | глубина очереди каждого движка |
| `WDOG_CYCLES` | 2^20 | порог watchdog (в тестах меньше) |

Производные: `BB = DW/8` = 32 байта на beat, `BURST_BYTES = BURST × BB` = 256.

**Размер окна и задержка памяти (закон Литтла).** В полёте до `NTAG × BURST` = 128 beat'ов. Окно держит 1 beat за такт, пока задержка «AR → последний beat» не превышает ~`NTAG × BURST` тактов. При большей задержке полоса падает как `NTAG × BURST / задержка`. Это показывается свипом в демо (§16). Измеренное поведение окна хорошо ложится на `NTAG × BURST / (L + 2 × BURST)`: слот удерживается примерно на один лишний BURST дольше, чем «AR → последний beat». Это эмпирическая подгонка, а механизм (вероятно, освобождение слота только после выдачи beat'ов burst'а в поток при коммите по порядку) — вывод из неё, трассой не проверен (см. `results/demo.md`).

## 4. Внешние интерфейсы `kshell_top`

- `clk`, `rst_n` — один домен, синхронный сброс, активный низкий.
- `s_axil_*` — AXI4-Lite slave, 32 бита данных, 12 бит адреса. Ответ всегда OKAY; чтение незанятого адреса возвращает 0.
- `m_axi_*` — AXI4 master, `DW` = 256, все пять каналов:
  - `ARID` = номер слота (log2 NTAG бит), `ARLEN` = BURST−1, `ARSIZE` = log2(BB), `ARBURST` = INCR, `ARCACHE` = `0011`;
  - `AWID` = 0 (константа), `AWLEN`/`AWSIZE`/`AWBURST` — как у AR, `AWCACHE` = `0010` (non-bufferable: B означает «данные в памяти»);
  - `WSTRB` = все единицы (STORE пишет полные слова);
  - `RREADY` = 1 всегда (§8.4), `BREADY` = 1 всегда;
  - `AxPROT` = `000`, `AxQOS` = 0, `AxLOCK` = 0.

## 5. Контракт с ядром

| Группа | Сигнал | Направление | Описание |
|---|---|---|---|
| Сброс | `k_rst_n` | shell → ядро | синхронный сброс ядра: `rst_n && !soft_reset` |
| Управление | `k_start` | shell → ядро | импульс 1 такт; запуск |
| | `k_arg[4][31:0]` | shell → ядро | аргументы, действительны в такте `k_start` (ядро защёлкивает) |
| | `k_done` | ядро → shell | импульс 1 такт; ровно один на каждый `k_start` (кроме случая `k_err`) |
| | `k_err` | ядро → shell | импульс; нарушение контракта, замеченное ядром |
| Поток | `k_s_tdata[DW]`, `k_s_tvalid`, `k_s_tready`, `k_s_tlast` | shell → ядро | AXI4-Stream; данные команд STREAM строго по порядку; `tlast` — на последнем beat'е каждой команды STREAM |
| Scratchpad | `k_spm_en`, `k_spm_we`, `k_spm_addr[log2 SPM_WORDS]`, `k_spm_wdata[DW]`, `k_spm_wstrb[DW/8]`, `k_spm_rdata[DW]` | ядро ↔ shell | порт B; чтение — данные через 1 такт после `en && !we` |

**Правила для автора ядра** (проверяются `kshell_kif_sva`):
1. **Один RUN — одна команда STREAM.** Ядро принимает поток только между `k_start` и `k_done` (`k_s_tready = 0` вне этого окна) и заканчивает приём на `tlast`.
2. Ядро обязано принять весь поток своего RUN. Если не принимает, поток стоит, а за ним стоит коммит rd_dma (§8.5).
3. Порт B scratchpad принадлежит только ядру.
4. Один `k_done` на каждый `k_start`; новый `k_start` не приходит, пока не выдан `k_done` предыдущего.
5. После `k_err` ядро может не выдавать `k_done`; восстановление — `SOFT_RESET`, который сбрасывает ядро через `k_rst_n` (§12).
6. Смысл аргументов определяет ядро, обёртка передаёт их как есть.

## 6. Модель программирования и формат команд

Хост записывает `CMD0..CMD3`, затем пишет любое значение в `DOORBELL`. Если командная FIFO полна, запись в `DOORBELL` игнорируется и ставится липкий флаг `STATUS.cq_ovf`. Он **не** является ошибкой (`ERROR` не ставится) и сбрасывается `SOFT_RESET`. Хост обязан проверять `cq_free` перед записью.

**Дескриптор (128 бит):**

| Поле | Биты | Описание |
|---|---|---|
| `op` | `CMD0[31:28]` | код команды |
| — | `CMD0[27]` | резерв, писать 0 |
| `sem` | `CMD0[26:24]` | номер семафора (log2 NSEM бит) |
| — | `CMD0[23:16]` | резерв, писать 0 |
| `spm_addr` | `CMD0[15:0]` | адрес в scratchpad, в словах |
| `hbm_lo` | `CMD1[31:0]` | адрес в памяти, младшие 32 бита |
| `hbm_hi` | `CMD2[7:0]` | адрес в памяти, старшие 8 бит |
| `len` | `CMD3[31:0]` | длина в байтах |

| `op` | Команда | Поля | Семантика | Завершена, когда |
|---|---|---|---|---|
| 1 | `LOAD` | `sem`, `spm_addr`, `hbm`, `len` | память → spm | все burst'ы пришли и закоммичены по порядку без ошибок; тогда `sem += 1` |
| 2 | `STREAM` | `hbm`, `len` | память → AXIS ядра | последний beat принят ядром |
| 3 | `STORE` | `sem`, `spm_addr`, `hbm`, `len` | spm → память | получены все B без ошибок; тогда `sem += 1` |
| 4 | `WAIT` | `sem`; `CMD1` = порог `thr` | секвенсор стоит, пока не станет истинным `$signed(sem − thr) >= 0` | условие истинно |
| 5 | `SIGNAL` | `sem`; `CMD1` = `inc` | `sem += inc` | сразу; **не является барьером**: не ждёт завершения ранее выданных команд |
| 6 | `RUN` | `sem`; `arg0` = `CMD1`, `arg1` = `CMD2`, `arg2` = `CMD3`, `arg3` = `CMD0[15:0]` (с расширением нулями) | запуск ядра | `k_done`; тогда `sem += 1` |
| 0, 7–15 | — | — | ошибка `BAD_OPCODE` | — |

**Проверки при декодировании** (ошибка → команда не выполняется, §12):
- `LOAD`/`STREAM`/`STORE`: `len ≠ 0`, `len % BURST_BYTES = 0`, `hbm % BURST_BYTES = 0`, `hbm + len ≤ 2^AW`, иначе `ALIGN`;
- `LOAD`/`STORE`: `spm_addr + len/BB ≤ SPM_WORDS`, иначе `RANGE` (сумма считается в 33 битах: `len/BB` бывает до 2^27).

Граница 4 KB не пересекается автоматически: burst'ы выровнены по 256 B, а 4096 кратно 256.

### 6.1. Правила корректной программы

Обёртка не ищет зависимости сама — их задаёт программа. Нарушение правил приводит к неверным данным или тупику (тупик диагностирует watchdog или хост по `STATUS`, но не лечит).
1. **Пары STREAM–RUN:** каждому RUN соответствует ровно одна STREAM; STREAM выдаётся до своего RUN; порядок пар STREAM совпадает с порядком RUN.
2. **Нет тупика head-of-line:** rd-движок обрабатывает LOAD и STREAM строго по порядку, а STREAM продвигается дальше `NTAG` burst'ов только при работающем ядре. Поэтому **нельзя ждать (WAIT) команду rd, стоящую в очереди после STREAM, раньше, чем выдан RUN, потребляющий эту STREAM**.
3. **Конфликты по данным:** между командами, чьи области spm или памяти пересекаются (LOAD → читающий RUN, RUN → STORE, STORE → LOAD в ту же область spm и т. п.), должен стоять WAIT на семафор первой команды.
4. **Семафор с несколькими командами:** команды, увеличивающие один семафор, могут завершиться в любом порядке. Надёжный барьер — `WAIT sem ≥ (число всех выданных на него приращений)`.

**Статический проверщик** (`tb/isa.py: check_program`) абстрактно исполняет программу (очереди движков, окно rd, ядро, семафоры) и отвергает программы, нарушающие правила 1–3. Все тесты прогоняют программы через него.

### 6.2. Пример: две задачи GEMV с перекрытием

`W` общий, `x0` и `x1` разные. K кратно 256, M кратно 64 (`4·M` кратно 256).

```
LOAD   sem0, spm=XA, hbm=x0, len=K
STREAM hbm=W, len=M·K                ; веса начинают идти заранее (заполняют окно и ROB)
WAIT   sem0 ≥ 1
RUN    sem1, x=XA, y=YA, M, K
LOAD   sem0, spm=XB, hbm=x1, len=K   ; грузится, пока RUN1 считает
STREAM hbm=W, len=M·K
WAIT   sem0 ≥ 2                      ; правило 2: RUN1 уже выдан → STREAM1 продвигается
RUN    sem1, x=XB, y=YB, M, K
WAIT   sem1 ≥ 1
STORE  sem2, spm=YA, hbm=y0, len=4·M ; выгружается, пока RUN2 считает
WAIT   sem1 ≥ 2
STORE  sem2, spm=YB, hbm=y1, len=4·M
WAIT   sem2 ≥ 2
SIGNAL sem7, 1                       ; хост опрашивает SEM[7]
```

**Базовая линия для сравнения** — та же работа, где после каждой команды стоит WAIT на её семафор (полностью последовательно). Демо сравнивает общее время и `KRN_BUSY / CYCLES`.

## 7. Секвенсор `cmd_seq`

- Берёт дескриптор из командной FIFO, когда `CTRL.ENABLE = 1` и нет ошибки. Не больше одной команды за такт.
- `cmd_no` (32 бита) — номер взятой команды; передаётся в движки вместе с командой (для `ERR_CMD`).
- Проверяет команду (§6). LOAD и STREAM идут в очередь rd, STORE — в очередь wr, RUN — в очередь ядра. Если нужная очередь полна, секвенсор стоит (perf не считается отдельно).
- `WAIT` блокирует выдачу следующих команд (perf `SEQ_WAIT`). Изменение семафора видно условию WAIT со следующего такта. `SIGNAL` выполняется сам.
- Движки работают независимо и параллельно. Порядок между ними задаёт только WAIT.
- Запуск ядра: команда из очереди ядра выдаётся как `k_start`, когда ядро свободно (`krn_busy = 0`). `krn_busy` ставится по `k_start`, снимается по `k_done` или `SOFT_RESET`. По `k_done` — `sem += 1` для семафора этого RUN, если нет ошибки (§12).
- При ошибке текущий WAIT **прерывается** (не может «пройти» на частично верных данных), командная FIFO и очереди движков **очищаются**.

## 8. rd-DMA (LOAD и STREAM)

### 8.1. Нарезка и выдача AR
Команда из очереди rd режется на `len / BURST_BYTES` burst'ов. Burst выдаётся, если в окне есть свободный слот, `ENABLE = 1` и нет ошибки (иначе резчик стоит на границе burst'а). Слот = `tail[log2 NTAG − 1:0]`, `ARID` = номер слота, адрес = `hbm + i × BURST_BYTES`. Не больше одного AR за такт. Слот занимается **в момент handshake** AR. Окно заполнено → perf `RD_WIN_FULL`.

### 8.2. Слот окна
`{type (LOAD/STREAM), spm_addr, beat_cnt, done, last_of_cmd, sem, cmd_no, t_issue}`; `t_issue` — счётчик тактов в момент handshake AR. Отдельно для каждой команды rd — накопитель ошибки `cmd_err` (OR по `RRESP` всех её burst'ов).

### 8.3. Приём R
Beat с `RID = s`:
- `type = LOAD` → запись в spm через порт A по адресу `spm_addr[s] + beat_cnt[s]` сразу, без переупорядочивания;
- `type = STREAM` → запись в ROB по адресу `{s, beat_cnt[s]}`; ROB — память `NTAG × BURST` слов по DW;
- `beat_cnt[s] += 1`; на `RLAST` → `done[s] = 1`, к `RD_LAT_SUM` добавляется `now − t_issue[s]`;
- `RRESP ≠ OKAY` → `cmd_err = 1` для команды слота и ошибка `RRESP_ERR` с `ERR_CMD = cmd_no[s]` (§12).

Beat'ы разных ID могут чередоваться: счётчики beat'ов независимы по слотам.

### 8.4. `RREADY = 1` всегда
Место для R-beat'а зарезервировано заранее: для LOAD — область spm (по правилу 3), для STREAM — строка ROB слота. Порт A spm у R-записей имеет абсолютный приоритет (§10). Канал R поэтому никогда не тормозит память.

### 8.5. Коммит по порядку (голова окна)
- голова `LOAD` и `done` → снять слот; если `last_of_cmd` и `cmd_err = 0` → `sem += 1`. Не больше одного слота за такт;
- голова `STREAM` и `done` → выдать BURST beat'ов из ROB в AXIS ядра. Чтение ROB идёт с задержкой 1 такт, поэтому на выходе стоит **skid-буфер на 2 записи** — так держится 1 beat за такт и при `tready = 0`. `tlast` — на последнем beat'е burst'а с `last_of_cmd`. После последнего beat'а слот снимается.

**Head-of-line blocking (сознательно).** Если ядро не принимает поток, голова STREAM стоит, и коммит последующих LOAD ждёт (perf `STRM_BP`; правило 6.1.2 исключает тупик). Альтернатива — раздельные окна LOAD и STREAM: нет блокировки, но вдвое больше состояния и второй пул тегов. Описана как вариант, не реализуется.

### 8.6. При ошибке (abort)
Резчик останавливается на границе burst'а (новые AR не выдаются). Все выданные AR получают свои R (`RREADY = 1`). Данные, пришедшие в ROB, **отбрасываются** — в AXIS они больше не выдаются; LOAD-данные остаются в spm, но семафоры не увеличиваются.

---

## 9. wr-DMA (STORE)

- Команда режется на burst'ы. На каждый burst: **сначала** прочитать BURST слов spm через порт A в W-FIFO (глубина 2 × BURST; чтения — только в такты, когда порт свободен от R-записей), **затем** выдать AW, затем выдать W подряд, `WLAST` на beat'е № BURST. Так W никогда не стоит после принятого AW (обёртка не держит канал записи интерконнекта).
- AW выдаётся, если в W-FIFO лежит полный burst, burst'ов записи в полёте меньше `WR_OUT` и нет ошибки.
- `AWID` = 0 для всех burst'ов → B приходят по порядку. Для каждого burst'а в полёте хранится `cmd_no` (FIFO глубиной `WR_OUT`). Когда получены все B команды и её накопитель ошибки `cmd_err = 0` → `sem += 1`.
- `BRESP ≠ OKAY` → `cmd_err = 1` и ошибка `BRESP_ERR` с `ERR_CMD` из FIFO.
- **Голодание порта A:** при непрерывном потоке LOAD wr-DMA ждёт свободных тактов порта A. Это не тупик (R не ждёт W), длительность ограничена длительностью LOAD. Видно по perf `WR_BURSTS` против времени.
- **При ошибке (abort):** новые AW не выдаются; для уже выданных AW дописывается W (данные уже в W-FIFO) и принимаются все B.

## 10. Scratchpad `spm`

- `SPM_WORDS × DW`, два порта. Порт A — DMA, порт B — ядро. Чтение с задержкой 1 такт, побайтовая маска записи на обоих портах.
- Арбитр порта A: R-записи rd_dma имеют абсолютный приоритет; wr_dma читает в свободные такты.
- Одновременный доступ портов A и B к одному адресу, при котором хотя бы одна сторона пишет, запрещён правилами (§5, §6.1.3) и ловится SVA; поведение памяти в этом случае не определено. Чтение A и чтение B одного адреса одновременно допустимо.

---

## 11. Семафоры `sem_file`

- `NSEM` 32-битных счётчиков.
- Источники приращений в одном такте: коммит LOAD (+1), завершение STORE (+1), `k_done` (+1), `SIGNAL` (+inc). Приращения на один семафор в одном такте суммируются.
- Запись хоста в `SEM[i]` задаёт значение и имеет приоритет над приращениями в том же такте.
- При ошибке приращения от движков и ядра подавляются.
- Новое значение видно со следующего такта (WAIT, чтение хостом).
- Сравнение для WAIT — знаковая разность (безопасно при переполнении, пока значения не разошлись больше чем на 2^31).

## 12. Ошибки, пауза, сброс, watchdog

### 12.1. Предикаты
- **`AXI_QUIET`** — нет выданных AR без последнего R, нет выданных AW без B, нет AW с недописанным W.
- **`IDLE`** — `AXI_QUIET`, командная FIFO и очереди движков пусты, окно rd пусто, W-FIFO пуста, выход AXIS пуст, `krn_busy = 0`, нет текущего WAIT, секвенсор не держит взятую команду (`seq_busy = 0`). «Вся работа выполнена».

### 12.2. Ошибки
**Коды `ERR_CODE`:** 0 — нет, 1 — `RRESP_ERR`, 2 — `BRESP_ERR`, 3 — `ALIGN`, 4 — `RANGE`, 5 — `BAD_OPCODE`, 6 — `KERNEL_ERR`, 7 — `TIMEOUT`. Фиксируется **первая** ошибка; при нескольких в одном такте — по приоритету `TIMEOUT > RRESP_ERR > BRESP_ERR > KERNEL_ERR > ALIGN > RANGE > BAD_OPCODE`. `ERR_CMD` — номер команды (для `KERNEL_ERR` — номер текущего RUN, для `TIMEOUT` — последней взятой команды).

**При ошибке (abort):**
1. `STATUS.ERROR = 1`; секвенсор не берёт команды; текущий WAIT прерывается; командная FIFO и очереди движков очищаются.
2. Резчики rd и wr останавливаются на границе burst'а; выданные транзакции AXI доводятся до конца (§8.6, §9). Ни одна транзакция AXI не бросается.
3. Семафоры больше не увеличиваются движками и ядром; данные ROB отбрасываются.
4. Ядро может остаться в середине RUN — его сбрасывает `SOFT_RESET` (`k_rst_n`).
5. Хост ждёт `STATUS.AXI_QUIET = 1` и делает `SOFT_RESET`.

### 12.3. Пауза (`CTRL.ENABLE = 0`)
Секвенсор не берёт команды и не выдаёт уже взятую (ничего не уходит в очереди движков); `k_start` тоже не выдаётся (команда RUN остаётся в очереди ядра); резчики rd и wr останавливаются на границе burst'а; выданные транзакции доводятся до конца. Когда `AXI_QUIET` — можно безопасно сбросить (`SOFT_RESET`) или продолжить (`ENABLE = 1`): работа возобновляется с того же места, текущий WAIT проверяется заново. Отдельного `HALT` нет — пауза и есть quiesce.

### 12.4. `CTRL.SOFT_RESET`
Выполняется только при `AXI_QUIET` (иначе игнорируется). Сбрасывает: командную FIFO, очереди, окно rd и ROB, W-FIFO, ошибку и `cq_ovf`, `cmd_no`, семафоры, perf-счётчики; держит `k_rst_n = 0` один такт (ядро сбрасывается, `krn_busy = 0`). Так как в полёте ничего нет, «опоздавших» R или B не бывает, и бит эпохи в ID не нужен.

Сброс **без** ожидания `AXI_QUIET` (для зависшей памяти) вне объёма. В реальной системе его делает decoupler, завершающий зависшие транзакции; вариант без decoupler — «слоты-зомби»: сохранить карту выданных транзакций через сброс и отбрасывать опоздавшие ответы.

### 12.5. Watchdog
Счётчик тактов растёт, **пока `AXI_QUIET = 0` и нет R-beat'ов и B** (ожидание ответа памяти); сбрасывается любым R или B. Достиг `WDOG_CYCLES` → `TIMEOUT`. Не срабатывает на паузе, на ожидании WAIT семафора от хоста и на медленном ядре — это не неисправность памяти. Зависание ядра хост видит по `KRN_BUSY` и лечит `SOFT_RESET`.

## 14. Perf-счётчики `kshell_perf`

32-битные, считают при `ENABLE`; `PERF_SNAP` копирует все одновременно в регистры чтения; `SOFT_RESET` обнуляет. Все события — по handshake.

| Адрес | Имя | Что считает |
|---|---|---|
| `0x080` | `CYCLES` | такты |
| `0x084` | `SEQ_WAIT` | такты секвенсора на WAIT |
| `0x088` | `RD_BURSTS` | handshake'и AR |
| `0x08C` | `RD_LAT_SUM` | сумма задержек от handshake AR до последнего R; средняя = `RD_LAT_SUM / RD_BURSTS` |
| `0x090` | `RD_WIN_FULL` | такты, когда у резчика rd есть burst, но окно полно |
| `0x094` | `STRM_BP` | такты `k_s_tvalid && !k_s_tready` |
| `0x098` | `WR_BURSTS` | handshake'и AW |
| `0x09C` | `KRN_BUSY` | такты `krn_busy` |

## 15. Демо-ядро `gemv_kernel`

**Функция:** `y[m] = Σ_k W[m][k] · x[k]`, `W` и `x` — INT8 со знаком, накопление и `y` — INT32 со знаком (переполнение по модулю 2^32, как в эталоне).

**Аргументы:** `arg0` — адрес `x` в spm (слова), `arg1` — адрес `y` в spm (слова), `arg2` — `M`, `arg3` — `K` (кратно 32).

**Раскладка:**
- `x`: K/32 слов, элемент k — в байте `k % 32` слова `k / 32`;
- `W`: поток строк, строка m — K/32 beat'ов, элемент k — в байте `k % 32` beat'а `k / 32`; всего M·K/32 beat'ов;
- `y`: 8 значений на слово, `y[m]` — в дорожке `m % 8` слова `arg1 + m / 8`, запись по `wstrb` на 32-битную дорожку.

**Микроархитектура:**
- на каждый принятый beat `W` — слово `x[beat % (K/32)]`, прочитанное из spm с опережением на такт;
- 32 умножения INT8 → дерево сумматоров (конвейер) → аккумулятор строки;
- в конце строки — запись `y[m]` через порт B; чтение `x` и запись `y` делят порт B, поэтому на границе строки возможен пропуск такта (`tready = 0`);
- целевой темп в установившемся режиме — 1 beat за такт за вычетом пауз на границах строк.

**`k_err`:** неверные аргументы в такте `k_start` (`M = 0`, `K = 0` или `K` не кратно 32; тогда ядро не стартует), либо `tlast` пришёл не на beat'е M·K/32, или на этом beat'е его нет. **`k_done`:** после записи последнего `y`.

## 16. Верификация

**Инфраструктура** — как в tick_to_trade: cocotb + Verilator, `make lint` (Verilator `-Wall` + Verible), прогоны с ассершенами и с покрытием раздельно (`VCOV=1`), SVA и covergroup в bind-файлах `rtl/<mod>_sva.sv` и `rtl/<mod>_cov.sv`.

**Модели на Python (`tb/`):**
- `hbm_model` — AXI4 slave:
  - память словарём байтов;
  - `N_PC` псевдоканалов (по умолчанию 8), PC = `(addr >> 8) % N_PC`;
  - у каждого PC очередь и случайная задержка из настраиваемого диапазона → ответы **out-of-order по ID**;
  - случайные паузы `ARREADY`/`AWREADY`/`WREADY`;
  - B по порядку для одного ID;
  - впрыск `SLVERR` по заданным адресам; режим «перестать отвечать» (для watchdog);
  - опционально: чередование R-beat'ов разных ID;
  - проверка протокола на стороне модели: `WLAST`, `AxLEN`, граница 4 KB.
- `axil` — драйвер AXI4-Lite.
- `isa` — кодировщик дескрипторов, построитель программ (`load()`, `stream()`, `store()`, `wait()`, `signal()`, `run()`), статический проверщик `check_program` (§6.1).
- Эталон GEMV на numpy.

**Тесты:**

| # | Тест | Проверяет |
|---|---|---|
| T1 | memcpy: LOAD → WAIT → STORE через spm, разные длины | данные, семафоры, OoO-ответы |
| T2 | STREAM в тестовое ядро-приёмник (`tb/sink_kernel.sv`, пишет поток в spm) | порядок потока при OoO, `tlast`, skid при `tready = 0` |
| T3 | GEMV, несколько (M, K) | результат против numpy |
| T4 | программа §6.2 и её последовательная базовая линия | результат; время меньше базовой линии; `KRN_BUSY / CYCLES` выше |
| T5 | впрыск SLVERR в LOAD, STREAM и STORE (ядро в середине RUN) | `ERROR`, код, `ERR_CMD`; WAIT прерван; семафор не вырос; `AXI_QUIET` наступает; `SOFT_RESET` → `IDLE`; следующая программа верна |
| T6 | пауза (`ENABLE = 0`) посреди программы → `AXI_QUIET` → продолжение | результат после продолжения верный |
| T7 | ошибки декодирования `ALIGN`, `RANGE`, `BAD_OPCODE`; переполнение командной FIFO | коды; `cq_ovf` без `ERROR` |
| T8 | watchdog: память перестаёт отвечать | `TIMEOUT`; нет ложного срабатывания на паузе и на долгом WAIT |
| T9 | случайные программы LOAD/STORE/SIGNAL/WAIT | память и семафоры против Python-модели |

**Генератор T9:**
- без STREAM и RUN, поэтому тупиков head-of-line нет;
- `WAIT sem ≥ N` только при N ≤ суммы уже выданных приращений на этот семафор;
- области spm и памяти каждой команды отслеживаются; перед пересекающейся командой (RAW/WAR/WAW) вставляется барьер `WAIT sem ≥ всего выданного`;
- в конце — общий барьер; сравниваются вся память, spm и семафоры.

**SVA (основное):**
- AXI4 master: `VALID` держится до handshake, полезная нагрузка стабильна; `ARLEN`/`AWLEN` = BURST−1; burst не пересекает 4 KB; число W-beat'ов на AW = BURST, `WLAST` на последнем; W не стоит после принятого AW дольше, чем W-FIFO отдаёт burst;
- окно rd: R только для слота в полёте; `RLAST` ⇔ `beat_cnt == BURST−1`; `tail − head ≤ NTAG`;
- AXIS к ядру: стабильность при `tvalid && !tready`;
- spm: нет двух источников записи в порт A в одном такте; нет одновременного доступа A и B к одному адресу, если хотя бы одна сторона пишет (чтение A и чтение B одного адреса — легально);
- `SOFT_RESET` действует только при `AXI_QUIET`.

**`kshell_kif_sva` (контракт ядра):** `k_done` только при `krn_busy`; ровно один `k_done` на `k_start` (если не было `k_err`); `k_s_tready = 0` вне `k_start..k_done`; ядро не обращается к порту B в такте `k_rst_n = 0`.

**Функциональное покрытие:**
- окно заполнено;
- расстояние out-of-order (насколько далеко от головы пришёл ответ): бины 0, 1–3, 4–7, 8+;
- чередование beat'ов разных ID;
- head-of-line блокировка (голова STREAM стоит при готовых LOAD за ней);
- все коды команд; стоянка на WAIT; WAIT прерван ошибкой;
- все коды ошибок; пауза во время трафика;
- W-FIFO полна; одновременные приращения одного семафора.

**Демо (`scripts/demo`):**
1. Прогон T4 с отчётом perf-счётчиков: средняя задержка чтения, `KRN_BUSY / CYCLES`, `STRM_BP`, `SEQ_WAIT`, время с перекрытием и без.
2. **Свип NTAG × задержка памяти:** полоса STREAM (beat'ов за такт) для NTAG = 4, 8, 16 и задержки 20…300 тактов — видно «колено», где окно перестаёт закрывать задержку (§3).

Числа в README помечаются: «симуляция с моделью памяти, не кремний».

## 17. Проектные решения (для разговора)

| Решение | Почему | Альтернатива и её цена |
|---|---|---|
| Ядро без AXI: поток + spm + start/done + сброс | сложность памяти — один раз в обёртке; ядро отдаётся контрактору как black box и проверяется `kshell_kif_sva`; DMA можно поставить у HBM, ядро — где угодно | AXI в каждом ядре: повторение тегов, OoO, ошибок; утечка системы к контрактору |
| Тег = номер слота окна | коммит по порядку бесплатен (как ROB); тег не нужно хранить | свободный список тегов: нужен отдельный ROB по порядку выдачи |
| LOAD пишет OoO, семафор — по порядку | данные не переупорядочиваются; потребитель видит только подряд готовое | переупорядочивать данные: лишняя память |
| `RREADY = 1` | память никогда не стоит из-за обёртки; место зарезервировано заранее | backpressure на R: потеря полосы памяти |
| W-FIFO наполняется до AW | канал записи интерконнекта не удерживается | AW сразу: меньше задержка, но W может стоять |
| Один `AWID`, `AWCACHE = 0010` | записи не переставляются; B означает «в памяти» — семафор не врёт | bufferable-записи: быстрее, но B раньше данных |
| Одно окно на LOAD и STREAM | проще, один пул тегов; цена — правило 6.1.2 | раздельные окна: нет head-of-line блокировки, вдвое больше состояния |
| Синхронизация только через семафоры + WAIT, программа проверяется статически | модель командных потоков NPU/TPU: зависимости явные, движки параллельны | неявные зависимости в железе: сложнее и менее гибко |
| Abort с доведением AXI-транзакций, сброс только при `AXI_QUIET` | ни одна транзакция не бросается; бит эпохи не нужен; ядро сбрасывается своим `k_rst_n` | сброс в любой момент: нужен decoupler или «слоты-зомби» |
